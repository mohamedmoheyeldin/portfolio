# Design brief: the workbench

The site is a working surface, not a brochure: it is laid out like a well-made engineering tool, opened on its owner's career record. A sidebar (or a top bar on narrow screens) is the navigation, a status bar reports where you are and which record the page reads from, projects are documents with properties, and two of them carry small working demonstrations. The full Scrollcraft brief (grammar, journey, feeling curve, score, signature move and fingerprint gate) is in [SCROLLCRAFT-BRIEF.md](SCROLLCRAFT-BRIEF.md).

- **Two themes, designed separately.** Light: a pale graphite ground, white panels, hairline borders, near-black ink. Dark: a blue-black ground with raised panels, lighter lines and brighter blues. One graphite scale (a neutral with a trace of blue) replaces the upstream neutral scale, so Untitled UI components and portfolio surfaces share the same greys. Blue is the signal: links, focus, the current place, selection and the primary action.
- **Type.** Inter for text and headings (tight tracking at display sizes, never more than about 4.75rem) and Geist Mono for labels, record paths, dates and figures. Two families. Headings stay moderate: on a working surface the content carries the page.
- **Panels with a purpose.** The profile, the work index, each project document, the demonstrations, the timeline, the stack matrix and the composer are panels because each is a real object you read or operate. Elsewhere hairlines and alignment do the grouping.
- **Evidence first.** Each project document: path and period, title, description, then the result with its evidence source (user-reported, public source, documented responsibility, derived from the record), role, context and tools in a properties column, and the problem, what I did, decisions and evidence in the body.
- **The inspector (signature move).** "Inspect sources" prints, beside every fact on the page, the career-record field it is rendered from and how it is evidenced, and the status bar totals the facts by evidence. It is computed from the record, never typed by hand.
- **Working demonstrations.** The Claims Document Assistant carries a rule-check demo (a synthetic claim; change any field and seven deterministic checks rerun and redraft the reply). Data Generator & File Processing carries a batch demo (synthetic values with the 999 / 555-01xx / example.com rules, a SHA-256 checksum and the gzip size computed in the browser). Both say on their face that they restate the project's documented rules on synthetic data and are not the project's code.
- **Motion.** Native CSS only, behind `prefers-reduced-motion: no-preference`, and scroll-driven parts behind `@supports (animation-timeline: view())`. The resting state is the visible state. No scroll-jacking, no pinning, no scroll cues, no section numbers (project numbers 01 to 06 are references the index, sidebar and matrix share).
- **Content rules.** Career facts come from `career.json`; no invented numbers, logos, generated imagery or mock interfaces. The demos are labelled re-implementations on synthetic data; the pipeline figure is an ordered list restating the project description.
- Existing resume documents keep their own layout. The web redesign does not change the PDF or Word output.
